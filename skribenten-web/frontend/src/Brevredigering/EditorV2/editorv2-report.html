1. Kort oppsummert

V1-editoren er krevende å jobbe med fordi datamodellen er tung: lister og tabeller ligger inne i avsnitt, og posisjoner angis med tre ulike indekstyper uten noe felt som skiller dem. Det fører til "itemIndex" in index-sjekker, casts, og at hver handling må ha egne grener for blokk, punkt og celle. Markup V2 legger lister og tabeller som egne blokker på toppnivå. Det gjør at all redigerbar tekst får samme form: en tekstbeholder med content og deletedContent. V2-editoren bygger hele arkitekturen på dette.

  • Mer enn halvparten mindre kode for samme funksjonalitet, selv når vi bare regner med den modellavhengige V1-koden.
  • Typesikker hele veien. Ingen casts, ingen in-sjekker, og alle switch-er dekker alle tilfeller.
  • Én modul eier ID- og sletteregler i stedet for over 150 spredte endringer i 15 filer.
  • Små, rene kommandoer (en per fil). split gikk fra 166 til 25 linjer.
  • Mindre forgreining: halvparten så mange beslutningspunkter, og funksjoner med kompleksitet over 10 gikk fra 46 til 10.
  • Noen V1-feil og V1-TODO-er er løst som en naturlig følge av strukturen (se avsnitt 6).

Forgreiningsanalyse

Tallene er målt med TypeScripts AST-parser, ikke med tekstsøk. Et beslutningspunkt er if, ? :, case, &&/||, løkker og catch. Kompleksiteten til en funksjon er 1 + antall beslutningspunkter i den, uten nestede funksjoner (McCabe). Kolonnen «V1, modellavhengig» trekker fra koden V2 gjenbruker, blant annet RTF-parseren og caretUtils.

3. Forbedringer som følger av V2-strukturen

3.1 Én tagget stitype i stedet for tre utaggede indekstyper

V1 – model/state.ts + bruk
type BlockContentIndex = { blockIndex; contentIndex };
type ItemContentIndex  = BlockContentIndex & { itemIndex; itemContentIndex };
type TableCellIndex    = BlockContentIndex & { rowIndex; cellIndex; cellContentIndex };
type LiteralIndex = BlockContentIndex | ItemContentIndex | TableCellIndex;

if ("itemIndex" in index) { … }
if ("rowIndex" in index)  { … }
const cell = event.target as HTMLElement;
V2 – model/paths.ts
type ContainerPath =
  | { kind: "title" }
  | { kind: "block";  block }
  | { kind: "item";   block; item }
  | { kind: "header"; block; column }
  | { kind: "cell";   block; row; cell };

type Caret = { path: ContainerPath; content; offset };

switch (path.kind) { … }   // kompilatoren sjekker at alle tilfeller er dekket

I V1 er tittelen blockIndex = -1, og innholdsindeksen betyr ulike ting avhengig av hvilke felt som finnes. I V2 er hver posisjon en beholder pluss en indeks inn i dens content, uansett hvor i brevet den er. Det er hovedgrunnen til at casts og in-sjekker er borte.

3.2 Lister og tabeller er egne blokker

I V1 er en liste et ITEM_LIST-element midt i et avsnitts content, og en tabell trenger «skilletekst» før og etter seg. Mange V1-funksjoner fantes bare for dette: normalizeTableSeparators, mergeFromItemList, splitting av avsnitt med blandet innhold, og tester for «avsnitt som slutter med liste». I V2 er en liste en ItemList-blokk og en tabell en Table-blokk. Ved overføringen ble omtrent 20 V1-testscenarioer droppet fordi de bare testet denne nestingen.

3.3 Samme diff-nøkler i backend og frontend

Backendens ContentIndexV2 (BLOCK_CONTENT, ITEM_CONTENT, COLUMN_SPEC_CONTENT, TABLE_CELL_CONTENT) bruker de samme beholdertypene som ContainerPath. diff/diffModel.ts oversetter direkte, med én switch som dekker alle tilfeller, og er halvparten så stor som i V1.

4. Forbedringer som følger av bedre abstraksjoner

4.1 Én modul eier ID- og sletteregler

model/collection.ts har insertAt, removeAt, move, transfer og replaceAll. Disse er de eneste funksjonene som endrer deleted*. Når et element fra malen fjernes, legges ID-en i slettelisten. Når det settes inn igjen, fjernes ID-en fra listen. Nye elementer får id = null. I V1 gjøres dette for hånd på rundt 158 steder med addElements/removeElements og lignende, hvor man selv må sende inn riktig sletteliste for riktig nivå. Det var en vanlig kilde til feil.

removeAt(collection(list.items, list.deletedItems, list), path.item);

4.2 Kommandoer som små, rene funksjoner

Alle endringer har typen Command<Args> = (draft, ...args) => void. De kjøres gjennom én run/dispatch, som tar seg av Immer-patcher, historikk og saveStatus. Kommandoene vet ikke noe om historikk eller lagring. Kommandoer som bare flytter fokus, havner ikke i angre-historikken. Kommandoer som bare gjelder brev (LetterCommand, f.eks. updateSignatur), gir kompileringsfeil hvis de brukes på et vedlegg.

4.3 Lagdeling med én oppgave per modul

EditorV2/ model/ paths (ContainerPath, resolve, containers, next/previous), collection (ID-/sletteregler), text (bare Text[]), structure (splitt/sammenslåing av beholdere), table, blockType, factories state/ editorState (run/apply/Command), history, createEditorAutosave, useEditorAutosave commands/ split, merge, addNewLine, updateText, deleteSelection, switchFontType, switchTypography, toggleList, table, tableTab, paste, pasteOverSelection, missingFromTemplate, updateSignatur clipboard/ htmlToElements, readClipboard, fitElements, buildTable caret/ domCaret (DOM ↔ Caret via data-path), navigation (opp/ned, Tab i tabeller) diff/ diffModel, AttestantDiffContextV2, DeletedMarkupV2, useAttestantLetterDiffV2 view/ EditorV2, BlockView, ListView, TableView, LetterChrome, menu/, text/ (TextContainerView, EditableLiteral, VariableView, useLiteralKeyboard)
  • Én gjennomgang av dokumentet: containers(doc) gir alle beholdere i dokumentrekkefølge. Markørbevegelse, sletting av markering, «første uredigerte fritekst», Tab i tabeller og pil opp/ned bruker alle denne i stedet for egne løkker.
  • Forskjellen mellom blokk, punkt og celle finnes bare ett sted, i structure.ts (insertSibling, removeContainer, breakOutOfList).
  • Samme komponent for all tekst: TextContainerView brukes for tittel, avsnitt, listepunkt, tabelloverskrift og celle. V1 har 864 linjer i ContentGroup.tsx med egne grener per type.
  • Én kobling mellom DOM og modell: attributtene data-path/data-content, som leses og skrives bare i caret/domCaret.ts.
  • Lim inn er delt i tre trinn: lese utklippstavlen → TraversedElement, sjekke hva som passer ved markøren, og sette inn. V1 har alt i én fil på 1 116 linjer.
  • Brev og vedlegg bruker samme editor: EditorV2<S extends EditorStateV2> er generisk. Saksinformasjon og signatur sendes inn som props.

5. Hva som er gjenbrukt fra V1

For en rettferdig sammenligning er modelluavhengig V1-kode importert direkte, ikke kopiert. Den er ikke regnet med som en V2-forbedring (ca. 2 430 linjer):

  • RTF-parser (actions/rtf/*) og AST-en TraversedElement
  • DOM-hjelpere for markøren (services/caretUtils: gotoCoordinates, linjedeteksjon)
  • Diff-segmenter (DiffSegments.tsx, buildDiffSegments, diffQueryState)
  • Små komponenter: TableContextMenu, InsertTableDialog, EditorUndoRedo, AttestantDiffMenu, tekster og hurtigtaster i utils.ts, editor.css

Historikk og autolagring er kopiert og gjort generiske (ca. 400 linjer i state/). De er regnet med i V2-tallene, så det er ingen gevinst der.

6. Endret oppførsel

Forbedringer og V1-TODO-er som er løst

  • Sletting av en markering som går fra et listepunkt inn i et avsnitt, slår dem sammen. Dette var en TODO i V1.
  • Lim inn av tekst<p>p1</p>etter foran en liste mister ikke lenger «etter», og listepunkter forsvinner ikke. V1 og V2 ble sammenlignet i 403 scenarioer: 400 ga likt resultat, og de 3 som skilte seg var V1-feil.
  • Når en liste limes inn rett etter en liste av samme type, blir de én liste. Fjernes avsnittene mellom to like lister, slås listene sammen.
  • Fet og kursiv fungerer per ord også i tabellceller. V1 endret hele cellen og flyttet markøren til start.
  • Bytte av skrifttype gjenbruker det opprinnelige elementet, så færre malelementer havner i deleted*.
  • Lim inn i tittelen setter inn ren tekst. V1 ignorerte det.
  • Det er funnet og rettet én reell markørfeil: pil venstre inn i forrige tekstbit plasserte markøren i starten i stedet for slutten.

Mangler sammenlignet med V1

  • Fet og kursiv virker bare på ordet ved markøren, ikke på en markert tekstbit. Kan legges til som et valgfritt markeringsargument.
  • Etter en variabel blir det alltid stående en tom tekstbit (["t1", var, ""]).
  • Versjonsvalget for lagrede brev: hvis V1-endepunktet svarer 409, hentes /brev/{id}/info, og V2 brukes hvis infoen sier det. Brev som allerede ligger i cache, sendes rett til riktig editor. Uten cache koster et V2-brev derfor ett ekstra kall.
  • V2-siden mangler fremheving av innsatt tekstvalg og sporing av diff-bruk.

8. Konklusjon

Den største gevinsten kommer av modellen. Når lister og tabeller er egne blokker og all tekst ligger i like beholdere, forsvinner de utaggede indekstypene, nestingen og de dupliserte grenene, som er hovedkildene til kompleksitet i V1. Abstraksjonene som bygger på dette (ContainerPath, collection, containers(), én TextContainerView) gir resten. Resultatet er omtrent halvparten så mye modellavhengig kode, null casts, ID-/sletteregler på ett sted, og kommandoer som kan leses på noen sekunder. Disse abstraksjonene kunne ikke bygges like rent på V1-modellen, fordi tre indekstyper med ulik betydning, nesting og skilletekst rundt tabeller ville trengt spesialtilfeller i hver av dem.
